# Этап 4 (первый экран). Настройки

Референс функциональности: `screens/settings/screen_ui.py` +
`screen_actions.py` (десктоп). Backend: `app/routers/settings.py` —
уже был в приложенном `lesovod_backend_stage2.zip`, эндпоинты не
менялись, только вызываются с фронта.

## Новые файлы

```
src/
├── api/
│   └── client.js          # единая точка HTTP-запросов (Authorization, разбор ошибок FastAPI)
├── components/
│   └── TextField.jsx      # подписанное поле ввода — новый атом, формы держатся на нём везде
└── pages/
    └── Settings.jsx        # сам экран
```

`App.jsx` и `Sidebar.jsx` обновлены: пункт «Настройки» теперь открывает
реальный экран вместо заглушки (и стал стартовым экраном по умолчанию).

## Перенесено 1:1

| Было (desktop) | Стало (веб) |
|---|---|
| Ключ OpenRouter API, показать/скрыть, сохранить | `GET/POST/DELETE /api/settings/secrets/openrouter` — маскированный статус, ключ никогда не приходит с сервера в открытом виде |
| Токен Telegram-бота | то же самое, `.../secrets/telegram` |
| ФИО / должность / лесничество лесничего | `GET/POST /api/settings/lesnichiy` |
| Выпадающий список лесничеств (editable combo) | `GET /api/settings/lesnichestva` → `<input list>` (datalist) |
| QR-код подключения мобильного приложения | переосмыслено: QR теперь ведёт на `window.location.origin` — на телефоне открывается тот же браузерный адрес, а не отдельное приложение |

## Сознательно упрощено (и почему — подробнее в комментарии в самом `Settings.jsx`)

1. **«Проверить ключ» / «Проверить токен»** — кнопки на месте, но
   задизейблены с подсказкой. Раньше проверка шла напрямую с десктопа на
   OpenRouter/Telegram; с браузера так делать нельзя (ключ утёк бы в
   клиентский код + CORS). Нужен отдельный проксирующий эндпоинт вида
   `POST /api/settings/secrets/{name}/test` — его пока нет в Этапе 1/2.
2. **«Общая база лесничества»** — убрана целиком: backend сам стал этой
   общей точкой, настройка теряет смысл при веб-архитектуре.
3. **Автозапуск при включении ПК / сворачивание в трей** — свойства
   desktop-процесса, не веб-клиента. Аналог (автозапуск backend'а как
   службы) — уже в Этапе 8 плана, не в этом экране.
4. **Путь к LibreOffice (soffice.exe)** — по-прежнему нужен (конвертация
   МДО идёт на сервере), но это теперь ОДНА серверная настройка на всех,
   а не десктопная «у каждого свой soffice.exe». Карточка не показана —
   под неё нет эндпоинта в `app/routers/settings.py`. Нужно добавить
   `GET/POST /api/settings/libreoffice-path` (+ проверка) по образцу
   секретов — это небольшая доработка backend'а, не фронтенда.

## Как проверить

```bash
cd frontend && npm install
# backend отдельно (см. lesovod_backend_stage2.zip):
#   cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload
npm run dev   # http://localhost:5173 — стартовый экран уже "Настройки"
```

Без запущенного backend экран корректно покажет карточку с ошибкой
загрузки (`ApiError` из `api/client.js` перехватывается и показывается
человеку, а не роняет страницу) — это тоже часть переноса, в
десктоп-версии таких сетевых сбоев просто не было.

`npm run build` проверен — 121 модуль, без ошибок.

# Этап 4 (второй экран). Дашборд

Референс функциональности: `screens/dashboard/screen.py` + `helpers.py`
+ `widgets.py` + `weather_card.py` + `weather_worker.py` (десктоп).
Backend: **`app/routers/dashboard.py` — написан заново в этом шаге.**
В отличие от `settings.py`, роутера под дашборд в приложенных архивах
не было (полного `lesovod_backend_stage2.zip` среди присланных файлов
нет вовсе — есть только исходный десктоп-проект и текущий фронтенд).

## Новые файлы

```
backend/app/routers/
└── dashboard.py           # GET /api/dashboard/summary,
                            # POST /api/dashboard/harvest-plan,
                            # POST /api/dashboard/weather/refresh
frontend/src/
├── components/
│   └── BarChart.jsx       # новый атом — парные столбцы план/факт (SVG,
│                           # без библиотеки графиков)
└── pages/
    └── Dashboard.jsx       # переписан с моковых данных на реальные
```

`backend/app/routers/dashboard.py` подключить в `app/main.py`:
`app.include_router(dashboard.router)`. Если у вас уже есть общий
`deps.py` с `get_db()`/аутентификацией — замените `_connect()` внутри
роутера на него, чтобы не дублировать логику соединения между
роутерами (см. подробное примечание в шапке файла).

## Перенесено 1:1

| Было (desktop) | Стало (веб) |
|---|---|
| 4 карточки-метрики (делянки/выполнено/заготовлено/очередь ИИ), тревожный вид карточки очереди ИИ | `GET /api/dashboard/summary` → `metrics` |
| Таблица "Активные делянки" (последние 5 неархивных, `_load_plots_table`) | `summary.plots` |
| Лента "ИИ-аналитика": перерубы (топ-3) → отчёты в очереди → последние акты → "критичных событий нет" (`_refresh_ai_insights`) | `summary.insights`, тот же порядок и та же арифметика (через `compute_items_totals`/`get_delyanka_items` из `screens/raskhod/balance.py`) |
| График "Обзор заготовки" за 6 месяцев + диалог "✏️ Задать план на месяц" (`styled_get_item`/`styled_get_double`) | `summary.chart` и `POST /api/dashboard/harvest-plan`, диалог — `Modal` + `<select>` + `TextField` |
| Карточка "Погода в лесу": температура/влажность/ветер/класс пожарной опасности, кнопка "🔄" (`WeatherWorker`, Open-Meteo) | `summary.weather` и `POST /api/dashboard/weather/refresh` — тот же URL и та же формула класса пожарной опасности (`_compute_fire_danger`) |

## Сознательно упрощено (и почему — подробнее в комментарии в `Dashboard.jsx`)

1. **Автообновление при каждом показе экрана** (`showEvent` в десктопе)
   — пока только загрузка при монтировании страницы + ручное
   обновление погоды. Регулярный опрос нужнее на экране "Документы"
   (Этап 5, статусы генерации), общий механизм имеет смысл завести там
   и переиспользовать здесь, а не дублировать отдельным таймером.
2. **«＋ Новый аудит делянки» и «Смотреть все»** — кнопки на месте, но
   задизейблены с подсказкой. Любопытная деталь при переносе: в
   десктопе они тоже ни на что не были подключены
   (`new_audit_button`/`view_all_button` без `.clicked.connect` в
   `screen.py`) — но по смыслу должны вести на экран «Делянки»,
   которого в вебе пока нет (следующий пункт Этапа 4 по плану).
3. **Клик по строке "Активные делянки"** (в десктопе — двойной клик,
   сигнал `plot_selected`) — по той же причине не подключён.
4. **График** — обычный SVG-компонент (`BarChart.jsx`) вместо
   QPainter-отрисовки; библиотека графиков не подключалась — один
   график из двух серий её не оправдывает.

## Важно: техдолг, обнаруженный при переносе (не блокирует экран, но стоит знать)

`compute_items_totals`/`get_delyanka_items` (нужны для перерубов в
ИИ-ленте) лежат в `screens/raskhod/balance.py`, а
`_compute_fire_danger`/`_wind_direction_to_text` — в
`screens/dashboard/helpers.py`. Сама логика в этих функциях Qt не
использует, но оба файла импортируют `PySide6.QtWidgets` в шапке — это
ровно тот случай, о котором предупреждал Этап 0 аудита ("если есть
импорты PySide6 — вынести Qt-специфичные куски наружу"), сделано
не было. `dashboard.py` импортирует их с `try/except ImportError`
(отказоустойчиво, как и `screen.py`), так что backend не упадёт
целиком, если PySide6 недоступен — просто лента ИИ-аналитики не будет
считать перерубы. Раз backend по плану крутится на "том самом
техническом ПК", где PySide6 уже стоит для десктопа — на практике
заработает и так, но это хрупко и не переедет на "чистый" сервер.
Правильное решение — вынести эти функции в новый Qt-свободный модуль
(например, `raskhod_calc.py`), на который будут ссылаться и
`screens/raskhod/balance.py` (Qt-экран), и backend.

## Как проверить

```bash
cd frontend && npm install && npm run build   # 122 модуля, без ошибок (проверено)
# backend:
#   добавить app.include_router(dashboard.router) в app/main.py
#   uvicorn app.main:app --reload
npm run dev   # http://localhost:5173, переключитесь на "Дашборд" в Sidebar
```

Без запущенного backend экран покажет карточку с ошибкой загрузки,
метрики — прочерки/скелетоны, но не упадёт (тот же `ApiError`-паттерн,
что и в «Настройках»).
