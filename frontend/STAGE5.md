# Этап 5. Делянки + документы

Референс функциональности: `screens/plots/screen_core.py` (+`screen_forms.py`,
`screen_documents.py` — по факту один и тот же модуль, разбитый на mixin-ы).
Backend: **не переписывался** — `app/routers/delyanki.py`, `documents.py`,
`tasks.py` уже были в `lesovod_backend_stage2.zip` и оборачивают
`delyanka.py`/`webext.py` без изменений. Единственная правка backend'а —
`dashboard.py` из Этапа 4 не был подключён в `main.py` этого архива;
подключил + перевёл его локальный `_connect()` на общий
`app.database.get_connection()` (WAL/busy_timeout), как и предлагала
шапка самого файла.

## Новые файлы

```
frontend/src/
├── hooks/
│   └── useTaskPolling.js   # pollTask(taskId) — опрос GET /api/tasks/{id}
│                           # до done/error, общий для импорта МДО и всех
│                           # 4 видов генерации документов
├── components/
│   └── TextAreaField.jsx   # многострочный атом (↔ TextField), под причины
│                           # рубки/вредителей/мероприятия/членов комиссии
└── pages/
    └── Plots.jsx            # сам экран
```

`api/client.js` дополнен `api.upload()` (multipart/FormData — нужен для
импорта МДО, которого не было в Настройках/Дашборде) и экспортом
`API_BASE_URL` (для прямых ссылок на скачивание документов).

`App.jsx`: добавлен пункт `plots` в `READY_SCREENS`. Экран сам управляет
своим тулбаром (поиск, "Показывать архивные", "Импорт МДО" — в левой
колонке), поэтому `search`/`primaryAction` в `TopBar` для него не включены
(та же логика, что у Settings/Dashboard — не дублировать элементы).

## Новое по сравнению с desktop

Секция "Документы" под вкладками — таблица (`DataTable`) сгенерированных
файлов делянки (`GET /api/documents/?delyanka_id=...`) со скачиванием и
удалением. В desktop-версии такого списка не было (генерация сразу
открывала файл через `_open_generated_file` / `subprocess`) — в браузере
это не работает, поэтому список документов с явным статусом
("готов"/"ошибка") — прямая замена этому шагу, а заодно то самое "+
документы" из названия этапа.

## Сознательно упрощено (и почему)

1. **Абрис** (`screens/plots/abris.py` + `screen_tree.py`, ~800 строк:
   `QWebEngineView` + JS-мост `QWebChannel`, отрисовка на канве через
   `clipper.min.js`/`jspdf.umd.min.js`/`html2canvas.min.js`) — **не
   перенесён**. Это отдельный canvas-редактор, а не форма; по явному
   решению в этом чате вынесен за рамки Этапа 5. Backend для загрузки
   готового PNG абриса уже есть (`POST /api/delyanki/items/{id}/abris`,
   `multipart/form-data`) — можно подключить как отдельный шаг, когда
   дойдёт очередь (например, canvas на `<canvas>`/SVG вместо
   QWebEngineView, с той же загрузкой на тот же эндпоинт).
2. **Создание/удаление пресетов комиссии** — есть только применение
   готового пресета (выпадающий список). Кнопки "💾 Сохранить как..." /
   "🗑" у каждой вкладки не перенесены — эндпоинты под них в backend уже
   есть (`POST`/`DELETE .../presets/...`), это чисто фронтенд-доработка
   по тому же паттерну, что формы "Настроек".
3. **Drag-and-drop файлов МДО на список** (`DropListPanel.filesDropped`)
   — заменён обычной кнопкой + выбором файлов в модалке.
4. **"Создать делянку вручную" (без МДО)** — в backend такого эндпоинта
   нет (`delyanka.py` создаёт делянку только через `create_delyanka_from_mdo`/
   `_batch`), поэтому и в вебе такой кнопки нет — это симметрично
   desktop-версии, а не упрощение веба.

## Как проверить

```bash
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload   # теперь включает и dashboard, и delyanki/documents/tasks

cd frontend && npm install && npm run build   # 125 модулей, без ошибок (проверено)
npm run dev   # http://localhost:5173, откройте "Делянки" в Sidebar
```

Без запущенного backend экран покажет пустое состояние списка + Toast с
ошибкой сети (тот же `ApiError`-паттерн, что и в «Настройках»/«Дашборде»).
