# Этап 5 (докрытие) — глобальный экран «Документы»

## Что было и чего не хватало

В `lesovod_backend_final.zip` / `lesovod_frontend_final.zip` документы уже
были — но только **внутри карточки конкретной делянки** (`pages/Plots.jsx`):
список файлов одной делянки, без сквозного просмотра по всем делянкам сразу.

Из плана переноса (Этап 5) не хватало ровно того, ради чего этап и
задумывался: одной таблицы по **всем** документам сразу, с фильтрами и
панелью массовых действий поверх выделенных строк.

Это докрытие сделано в 2 части — backend и frontend.

---

## Часть 1 — Backend (изменены 2 файла, остальное не тронуто)

### `backend/legacy/webext.py`
- `list_documents()` — добавлены параметры `created_by`, `date_from`,
  `date_to` (фильтр по дате — включительно, по `date(created_at)`).
- `list_document_authors()` (новая) — список уникальных `created_by` для
  выпадающего фильтра «Автор» на фронте.
- `bulk_delete_documents()` (новая) — удаляет несколько записей по списку
  id разом, возвращает результат по каждому (`ok`/`не найден`), чтобы
  роутер мог почистить файлы с диска и сообщить, если что-то уже было
  удалено кем-то другим.

### `backend/app/routers/documents.py`
- `GET /api/documents/` — принимает новые фильтры, в каждой строке ответа
  теперь есть `file_size` (байты, читается с диска на лету — отдельной
  колонки под это в схеме не заводилось).
- `GET /api/documents/authors` — отдаёт список авторов.
- `POST /api/documents/bulk-delete` — тело `{"ids": [1,2,3]}`, удаляет
  записи и файлы с диска.
- `POST /api/documents/bulk-zip` — тело `{"ids": [1,2,3]}`, отдаёт zip
  (`StreamingResponse`) из документов в статусе «готов»; документы без
  готового файла молча пропускаются (за это отвечает статус в таблице,
  фронт может предупредить пользователя сам).

Существующие эндпоинты (`get`, `download`, `delete` по одному документу)
не менялись.

## Часть 2 — Frontend (1 новый файл + 2 точечных правки)

### `frontend/src/pages/Documents.jsx` (новый)
Таблица `DataTable` (уже была в дизайн-системе, с чекбоксами) по всем
делянкам сразу:
- Столбцы: тип документа, делянка, дата создания, автор, статус
  (`StatusBadge`), размер, действия (скачать/удалить).
- Фильтры сверху: тип документа, статус, автор (выпадающие списки),
  диапазон дат (два `TextField` type="date").
- Сортировка по каждому столбцу (уже умеет `DataTable`).
- Панель массовых действий появляется, когда выделена ≥1 строка:
  «Скачать выбранное (.zip)» → `POST /bulk-zip`, «Удалить» → модалка
  подтверждения → `POST /bulk-delete`, «Снять выделение».
- Опрос: пока в списке есть документ в статусе «в процессе»/«в
  очереди» — список перезапрашивается раз в 2 секунды; при переходе
  строки в «готов» — `Toast` с кнопкой «Скачать», при переходе в
  «ошибка» — `Toast` с текстом ошибки. Отдельного `task_id` на документ
  API не отдаёт, поэтому опрашивается сам список `/api/documents`, а не
  `/api/tasks/{id}` — результат для пользователя тот же.
- Пустое состояние — через `EmptyState` (уже была в `DataTable` из коробки).

Все запросы — через существующий `api` из `api/client.js`, кроме скачивания
файла и zip-архива (бинарный ответ — качается напрямую через `fetch` +
`Blob`, в обход `api.get/post`, которые ожидают JSON/текст).

### `frontend/src/App.jsx`
- Импортирован `Documents`, добавлена запись `documents` в `READY_SCREENS`.

### `frontend/src/components/Sidebar.jsx`
- Добавлен пункт меню «Документы» (между «Делянки» и «Таксация») со своей
  иконкой `IconDoc`.

Новых зависимостей нет, существующие компоненты (`Card`, `Button`,
`TextField`, `DataTable`, `StatusBadge`, `Toast`, `EmptyState`) не менялись.

## Как накатить

1. Замените в своём backend два файла: `legacy/webext.py`,
   `app/routers/documents.py`.
2. Добавьте/замените во frontend: `src/pages/Documents.jsx` (новый),
   `src/App.jsx`, `src/components/Sidebar.jsx`.
3. Перезапустите uvicorn и пересоберите/перезапустите dev-сервер
   фронтенда (`npm run dev` подхватит новый файл сам).
4. Проверка: `/docs` backend'а должен показывать `bulk-delete`/`bulk-zip`
   в разделе `documents`; в интерфейсе в сайдбаре должен появиться пункт
   «Документы» с таблицей по всем делянкам.

## Что сознательно не делалось (осталось за рамками этого докрытия)

- Полноценный предпросмотр docx в браузере (план прямо называет это
  отдельной опцией через LibreOffice headless, не частью Этапа 5).
- WebSocket вместо опроса раз в 2 секунды — план допускает оба варианта
  («через опрос статуса или WebSocket»), выбран опрос как более простой
  и не требующий нового транспорта на backend.
- Действия «Отправить» и «Архивировать» из панели массовых действий
  (в плане — два из четырёх пунктов) — не реализованы:
  - «Отправить» — в проекте нет ни email/Telegram-получателя, ни
    эндпоинта под это ни в одном из архивов; добавлять его без понимания,
    куда именно «отправлять», значило бы придумывать интеграцию с нуля.
  - «Архивировать» — у документа есть статусы `готов/в процессе/ошибка`,
    отдельного статуса `архив` схема не заводит (в `StatusBadge` он
    предусмотрен как пресет, но нигде не выставляется) — добавление
    потребовало бы отдельного решения, что значит «архивный документ»
    для остального приложения (скрывать из списка по умолчанию? хранить
    файл или нет?), это отдельная небольшая задача, не сделанная в
    рамках этого докрытия.
  Сделаны два из четырёх пунктов панели: «Скачать выбранное (.zip)» и
  «Удалить».
